# CampusClaw 项目冒烟测试缺陷清单

测试日期：2026-07-22  
测试范围：H5 前端（`5173`）及本机 API 连通性（`8000`）  
测试方式：真实浏览器页面巡检、未登录访问路径检查、接口连通性检查。未执行压力、安全渗透、跨端真机和完整登录后业务流测试。

## 测试覆盖

| 模块/页面 | 结果 | 说明 |
| --- | --- | --- |
| 论坛首页、搜索、分类入口 | 失败 | 页面可渲染，但帖子请求失败，列表为空。 |
| 匹配首页 | 通过 | 组队、恋爱、交易入口及底部导航正常呈现。 |
| 消息、我的 | 通过 | 未登录引导正常呈现。 |
| 登录页 | 部分通过 | 表单与演示账号入口正常呈现；实际登录因接口不可达无法完成。 |
| 资料、黑名单、发帖、聊天、审核、AI 助手 | 通过 | 未登录时均会跳转登录页。 |
| 组队、恋爱、交易广场 | 部分通过 | 页面可渲染；依赖接口的内容无法验证。 |
| 交易发布页 | 存在问题 | 未登录用户可直接通过 URL 打开发布表单。 |

## 缺陷清单

| 编号 | 优先级 | 缺陷描述 | 复现步骤 | 实际结果 | 建议 |
| --- | --- | --- | --- | --- | --- |
| BUG-001 | P0 | 前端 API 地址固定为不可达的内网 IP，导致核心数据与登录功能不可用。 | 1. 打开 `http://[::1]:5173`；2. 等待论坛首页请求结束。 | 页面显示 `request:fail`，帖子列表为 0；演示账号登录也无法完成。前端配置为 `http://10.54.173.45:8000/api/v1`，该地址在当前环境请求超时；而 `http://127.0.0.1:8000/api/v1/forum/posts/` 可正常返回 `200 []`。 | 将 API 基地址改为可按环境注入的配置（例如 Vite 环境变量）；本地开发默认使用 `http://127.0.0.1:8000/api/v1`，部署环境使用对应服务地址。 |
| BUG-002 | P2 | 未登录用户可直接访问交易发布表单，前端未做访问控制。 | 在未登录状态直接访问 `http://[::1]:5173/#/pages/trade/create`。 | 显示完整的交易发布表单，可输入内容；与交易广场“登录后才能查看和发布”的提示不一致。后端虽要求认证，但用户会在填写后才可能收到失败结果。 | 在交易发布页的 `onShow`/`onMounted` 中调用统一鉴权逻辑，未登录时保存回跳地址并跳转登录页。 |
| BUG-003 | P2 | 接口故障时向用户暴露底层错误文本，且论坛页缺少明确重试入口。 | 断开/配置错误的 API 地址后打开论坛首页，等待请求结束。 | 页面直接显示 `request:fail`，无法说明问题，也没有显式“重新加载”按钮。 | 将网络异常统一转换为用户可理解的提示（如“服务暂时不可用，请稍后重试”），并在论坛、组队等列表页提供重试按钮。 |

## 备注

- 本轮未发现页面白屏、路由死链或浏览器运行时异常。
- 当前最应优先修复 BUG-001；修复后再执行一次登录后回归，覆盖发帖、组队申请、聊天、交易发布、收藏与审核等写入操作。
