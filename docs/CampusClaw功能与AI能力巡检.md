# CampusClaw 功能与 AI 能力巡检

更新时间：2026-05-28

本文用于记录当前项目整体状态、内置 AI 能力、已发现风险，以及后续建议补齐的功能。当前项目主要由两部分组成：`apps/api` 是 Django 后端，`apps/mp` 是 uni-app 微信小程序端。

## 1. 本次巡检结论

当前项目已经不是纯 demo，论坛、匹配、消息、个人资料、微信登录、AI 助手动作卡片等主链路都已有前后端实现，并且本次巡检验证通过：

- 后端检查：`python manage.py check` 通过。
- 后端测试：`python -m pytest tests -q` 通过，结果为 `26 passed`。
- 小程序构建：`cmd /c npx pnpm --dir apps/mp build:mp-weixin` 通过。

当前仍需要重点关注的不是“能不能编译”，而是以下几类问题：

- AI 动作生成还偏规则化，不能完全算“模型自主理解页面并稳定提取结构化参数”。
- 真实微信登录、真实大模型、真机请求域名、图片存储等生产链路仍需要进一步联调。
- 双账号或生产环境相关的端到端测试仍需继续覆盖，例如聊天互通、组队申请、交易收藏、恋爱匹配互动、真实微信登录和真机 HTTPS 访问。
- 文档里仍有一些旧结构、旧 demo 说明，需要后续统一清理。
- 当前仓库存在未提交改动和少量运行日志文件，后续整理版本时需要处理。

### 已完成事项

- 单账号主链路已完成手动验收：论坛、组队、交易、恋爱匹配、我的页面等基础创建、编辑、筛选、查看流程已跑通。
- AI 单账号能力已完成手动验收：独立 AI 页面、半屏 AI、生成草稿、生成动作卡片、仅填充、填充并发布等单账号可测链路已跑通。
- 需要两个真实账号或真实生产环境的链路暂未纳入本轮完成范围，仍保留在后续路线和上线前检查清单中。

### 近期新增实现

- 独立 AI 页面和半屏 AI 的消息流滚动改为 `scrollTop` 驱动，不再依赖不稳定的锚点滚动。
- AI 对话内容不足一屏时保持自然展示；内容超过可视区后，新气泡、思考气泡、AI 回复和动作卡片会稳定跟随到底部。
- 半屏 AI 点击“重新开始”会强制创建新的 AI 会话，不再复用同一页面上下文下的旧 session。
- AI 思考气泡和动作卡片显示恢复逻辑增强：请求慢或后端稍后落库时，前端会继续轮询拉回回复，避免只剩用户气泡或需要重进页面才能看到结果。
- 头像、论坛图片、聊天图片上传增加大小、扩展名和 MIME 类型校验，并返回中文错误提示。
- 聊天页改为 `scrollTop` 驱动滚动，新增消息时间分割，图片消息继续支持点击预览。
- 交易列表新增状态标签；我的交易支持在单账号下切换出售中、已预定、已完成、已关闭。
- 登录页新增本地调试/管理员邮箱密码登录入口，管理员账号会跳过普通用户资料补全。
- 管理员审核台新增交易举报处理、关闭违规交易、最近审核操作日志展示。

## 2. 当前已实现的产品功能

### 微信登录与用户体系

- 支持微信一键登录后换取 JWT。
- 支持本地开发环境下的邮箱密码调试登录逻辑，管理员可通过 `createsuperuser` 创建后直接登录小程序。
- 用户有后端唯一主键 `User.id`，类型是 UUID。
- 用户有对外联系 ID `claw_id`，适合给“搜索联系人”使用，不需要暴露数据库主键、邮箱或 openid。
- 支持个人资料补全、头像、昵称、简介、专业、年级、兴趣等基础资料。
- 管理员账号会跳过普通用户资料补全，并在“我的”页显示管理员标识和管理后台入口。

### 论坛

- 支持帖子列表、搜索、分类筛选、只看我的帖子。
- 支持发布帖子、编辑帖子、帖子详情、图片上传。
- 支持帖子点赞、评论、回复评论、评论点赞。
- 支持联系发帖人。
- 支持帖子举报和管理员侧处理。

### 匹配入口

- 底部“匹配”页作为入口，承接组队匹配、恋爱匹配、交易匹配。
- 论坛顶部也保留组队匹配、恋爱匹配等快速入口。

### 组队匹配

- 支持组队广场、搜索招募、发起组队。
- 支持填写目标人数、当前人数展示。
- 支持申请加入、查看我的申请、查看收到的申请。
- 支持通过或拒绝申请。
- 支持联系发起人。

### 恋爱匹配

- 支持首次进入后填写展示资料。
- 支持性别、身高、体重、年龄、兴趣、简介、是否公开展示。
- 支持匹配偏好，包括性别、身高范围、体重范围、年龄范围、兴趣偏好。
- 支持候选人列表、感兴趣、跳过、匹配结果。
- 支持拉黑和举报候选人。

### 交易匹配

- 支持交易列表、搜索、筛选、发布交易内容。
- 支持交易类型、描述、价格、成色、标签、是否可议价。
- 支持交易状态展示和作者侧状态流转，包括出售中、已预定、已完成、已关闭。
- 支持收藏交易帖子。
- 支持联系发布者。
- 支持非作者举报交易帖子，管理员可在审核台关闭违规交易。

### 消息与联系

- 支持通知列表和聊天会话列表。
- 支持通过 `claw_id` 或昵称搜索联系人。
- 支持发起或进入私聊。
- 聊天界面支持文字消息和图片消息。
- 已按用户要求去掉拍照入口，图片发送以选择图片为主。
- 支持隐藏会话、已读、WebSocket 实时通信相关能力。

### 我的页面与安全

- 支持展示个人基础信息、资料完整度、我的内容入口。
- 支持黑名单管理。
- 拉黑已和聊天、匹配候选人等模块做了基础联动。

### 内容治理

- 支持举报帖子、举报匹配用户。
- 支持举报论坛评论和交易帖子。
- 支持管理员查看举报、筛选举报、处理举报、删除违规帖子、删除违规评论、关闭违规交易。
- 支持管理员审核操作日志，展示最近删除帖子、删除评论、关闭交易等操作。
- 后续仍需要增强用户封禁、权限细分和更完整的内容安全审核能力。

### 管理员账号创建与登录

本地开发时可以通过 Django 命令创建管理员账号：

```powershell
conda run -n aigc python apps/api/manage.py createsuperuser
```

如果当前终端已经在 `apps/api` 目录：

```powershell
conda run -n aigc python manage.py createsuperuser
```

创建时填写的 `Email` 和 `Password` 就是小程序登录页“本地调试 / 管理员”表单使用的账号。管理员账号满足 `role=admin`，登录后会跳过普通用户资料补全，默认进入或可从“我的”页进入管理后台。

管理员当前可用功能：

- 查看举报统计：全部、待处理、处理中、已解决、已驳回。
- 按类型筛选举报：论坛帖子、论坛评论、交易帖子。
- 处理举报状态：设为处理中、标记解决、驳回举报。
- 执行内容处理：删除论坛帖子、删除论坛评论、关闭交易帖子。
- 查看最近审核操作日志。
- 复制 Django Admin 地址，进入 Django 原生后台继续管理。

管理员功能测试顺序：

1. 普通账号发布一条交易帖子。
2. 非作者账号在交易页点击“举报”。
3. 管理员邮箱密码登录小程序。
4. 进入“我的”页，点击“管理后台”。
5. 筛选“交易举报”，点击“关闭交易并结案”。
6. 查看“最近审核操作”，确认出现“关闭交易帖子”。
7. 回交易广场确认该交易不再公开展示。

## 3. 内置 AI 当前可以做什么

当前 AI 已经从“只聊天”升级为“聊天 + 动作卡片”。前端有半屏弹层 AI 和独立 AI 页面，后端有会话、消息、动作草案和动作执行接口。

### AI 基础聊天

- 可以根据当前页面场景回答问题。
- 可以结合最近几轮历史对话回复。
- 可以通过 `config.yaml` 或环境变量配置大模型 `api_key`、`base_url`、`model`。
- 如果大模型配置不可用，后端有兜底回复逻辑，保证页面不至于直接崩掉。

### AI 动作卡片

AI 回复后，后端会生成一个动作草案 `AssistantActionProposal`。前端动作卡片提供三个选择：

- `填充并发布`：用户确认后，后端代执行对应业务动作。
- `仅填充`：把 AI 生成的内容写入目标页面草稿，用户自己再修改和提交。
- `仅生成`：只保留 AI 文本建议，不写入表单，也不执行接口。

所有代执行动作都要求用户确认，不做自动发布。

### AI 已支持的动作范围

- 论坛：发布帖子、评论帖子、回复评论、点赞帖子、点赞评论。
- 组队：发布组队招募、申请加入组队。
- 交易：发布交易帖子、收藏交易帖子。
- 恋爱匹配：保存展示资料、保存匹配偏好、发送感兴趣或跳过信号。
- 消息：生成并发送私聊消息，但必须用户确认。
- 个人资料：填充或保存基础资料。

### AI 明确不支持的动作

为了避免高风险误操作，当前 AI 不应该代执行以下动作：

- 删除帖子、删除评论、删除交易内容。
- 拉黑、解除拉黑、隐藏会话。
- 管理员审核、封禁、删除用户内容。
- 绕过用户确认直接发布或发送私聊。

## 4. AI 能力当前边界和风险

### 动作生成还不够智能

当前 AI 的自然语言回复会调用大模型，但动作卡片的类型选择主要还是后端规则判断，例如根据页面类型和关键词猜测 `forum_post_create`、`team_post_create` 等。它还没有做到让模型严格输出结构化 JSON，再由 schema 校验后生成动作。

影响：

- 用户表达复杂时，可能生成错误动作类型。
- 字段提取比较粗糙，例如价格、人数、年龄范围等不一定能稳定拆出来。
- 当前通常每次只生成一个动作，不支持“先发帖再评论”这类多步骤计划。

### 上下文还不够完整

部分动作依赖目标 ID，例如评论需要 `post_id`，聊天发送需要 `thread_id`，点赞评论需要 `comment_id`。如果 AI 是从底部半屏入口打开，但当前页面没有传入明确目标，动作可能缺少必要参数。

建议后续增强：

- 每个页面打开 AI 时传入更完整的 `context_target_type` 和 `context_target_id`。
- 帖子详情页传入帖子 ID，评论区传入评论 ID。
- 聊天页传入会话 ID。
- 组队、交易、恋爱候选人卡片传入对应对象 ID。

### 仅填充能力需要继续覆盖页面

当前已有 `assistant.pending-draft` 草稿机制，但每个目标页面都需要主动读取并应用草稿。如果某个页面没有接 draft adapter，`仅填充` 可能无法生效。

建议后续逐页验收：

- 发帖页：标题、正文、分类、标签。
- 帖子详情：评论框、回复框。
- 组队创建页：标题、摘要、详情、人数、标签、技能。
- 交易创建页：标题、描述、价格、类型、成色、标签。
- 恋爱匹配页：展示资料、匹配偏好。
- 聊天页：输入框内容。

### 真实大模型联调还需要单独验证

自动化测试不会真正请求外部大模型，因此只能证明代码路径可运行，不能证明当前 `config.yaml` 填写的服务一定可用。

上线前需要验证：

- `AGENT_API_KEY` / `config.yaml` 配置正确。
- `AGENT_BASE_URL` 能访问。
- 模型返回格式兼容 OpenAI 风格 `/chat/completions`。
- 超时、空回复、鉴权失败时前端提示友好。

## 5. 当前发现或建议关注的问题

### 已验证不是阻塞的问题

- `pages.json` 文件本身是正常 UTF-8 中文，PowerShell 里显示乱码是终端输出编码问题，不代表文件一定损坏。
- 小程序构建里的 Sass `legacy-js-api` 是依赖警告，不影响当前构建。
- Node 的 circular dependency 警告暂时不阻塞构建。

### 需要后续处理的问题

- 常见运行日志已加入忽略规则，后续如果本地产生 `*.log` 文件不要提交。
- 本轮未在仓库中发现 `docs/待实现功能清单.md` 和 `docs/后端待实现功能清单.md`，旧阶段文档清理暂不作为阻塞项。
- 真实微信登录需要确认 `WECHAT_MINIAPP_APPID` 和 `WECHAT_MINIAPP_SECRET` 已配置，并且微信开发者工具项目 AppID 与后端配置一致。
- 真机调试不能直接访问电脑上的 `127.0.0.1`，需要局域网 IP 或线上 HTTPS 后端。
- 图片上传当前已有基础安全校验，但仍依赖后端媒体目录；生产环境建议接对象存储或静态媒体服务。
- 管理员后台已有举报处理、评论删除、交易关闭和操作日志；后续仍缺少用户封禁、权限细分和自动内容安全审核。
- 通知和聊天中仍可能有少量英文接口返回文案，建议最后做一次全局中文化巡检。

## 6. 后续建议实现路线

### 第一优先级：把现有主链路验稳

- 用两个真实账号测试微信登录、联系搜索、发起聊天、文字消息、图片消息。
- 用两个账号测试组队申请、审核、联系发起人。
- 用两个账号测试恋爱匹配的感兴趣、跳过、匹配结果、拉黑联动。
- 用两个账号测试交易发布、收藏、联系发布者。
- 用真实微信 AppID 和 Secret 测一遍 `request.fail`、域名、HTTPS、真机访问。

### 第二优先级：补 AI 动作的稳定性

- 把 AI 动作生成从关键词猜测升级为结构化 JSON 输出。
- 给每个 skill 增加更严格的 schema 校验和中文错误提示。
- 支持一次回复多个候选动作，但执行时仍要求用户逐个确认。
- 为 AI 动作补测试：越权 action id、过期 action、缺少目标 ID、非法 payload、重复执行。
- 给前端动作卡片增加失败后的“仅填充重试”入口。

### 第三优先级：补生产化能力

- 图片上传继续补压缩、上传进度和对象存储。
- 接入对象存储或可靠媒体服务。
- 增加内容安全审核，例如图片和文本敏感内容检查。
- 继续增强管理员能力，例如用户封禁、权限细分和更完整的自动审核。
- 整理旧文档和启动说明，只保留当前 API + 小程序结构。

### 第四优先级：产品体验增强

- 联系人搜索支持二维码名片或复制 `claw_id`。
- 聊天页继续补失败重发。
- 论坛增加收藏、热度排序、标签页。
- 交易继续补交易详情页和更完整的状态操作体验。
- 恋爱匹配增加隐私开关、资料可见范围、推荐原因说明。
- AI 增加页面级快捷技能，例如“帮我润色这个帖子”“帮我写联系 Ta 的第一句话”“帮我把这段话变礼貌一点”。

- 小程序 `BASE_URL` 指向 HTTPS 后端，而不是 `127.0.0.1`。
- 微信公众平台配置了合法请求域名。
- 数据库迁移已执行。
- 媒体文件能被小程序访问。
- 管理员账号、举报处理、日志查看可用。
- AI 配置可用，并且失败时不会影响普通发帖、聊天、匹配功能。
- 使用两个以上账号完成论坛、组队、恋爱匹配、交易、聊天、AI 动作卡片的端到端测试。
